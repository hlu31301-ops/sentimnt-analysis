# 03. 프론트엔드 (HTML/CSS/JS) 구현 지침

## 1. 구현 범위
- `public/index.html`: 시맨틱 태그를 활용한 웹 페이지 구조 작성
- `public/app.js`: 사용자 입력 검증, 백엔드 API(`POST /api/analyze`) 호출, 로딩 상태 관리, 결과 및 오류 화면 렌더링

## 2. 상세 기능 명세
1. **입력 검증**:
   - 사용자가 아무것도 입력하지 않거나 공백만 입력하고 버튼을 누르면 API 요청을 보내지 않고, `"분석할 텍스트를 입력해주세요."`라는 오류 메시지를 표시합니다.
2. **로딩 상태 처리**:
   - API 요청 중에는 버튼을 비활성화(`disabled = true`)하고, 버튼 텍스트를 `"분석 중..."`으로 변경하여 중복 클릭을 방지합니다.
3. **결과 렌더링**:
   - 서버로부터 받은 JSON 데이터(`sentiment`, `confidence`, `reason`)를 화면에 출력합니다.
   - `sentiment` 값에 따라 결과 카드의 뱃지 색상(긍정/부정/중립)을 동적으로 변경합니다.
   - `confidence` 값(예: `92`)을 `"92%"`로 표시하고 프로그레스 바의 `width`를 `92%`로 설정합니다.
4. **오류 처리**:
   - 서버 응답이 `200 OK`가 아니거나 네트워크 오류가 발생하면, 서버가 보낸 오류 메시지 또는 `"일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요."`를 화면에 표시합니다.

## 3. 제약 조건
- `alert()` 창을 사용하지 마세요. 모든 안내와 오류는 HTML 화면 내 지정된 영역에 표시해야 합니다.
- 외부 UI 라이브러리(Bootstrap, jQuery 등)를 사용하지 마세요.

## 4. 완료 및 검증 기준
- 빈 값 입력 시 오류 메시지가 정상 출력되는지 확인합니다.
- 정상 텍스트 입력 시 로딩 상태 전환 후 결과가 화면에 표시되는지 확인합니다.
